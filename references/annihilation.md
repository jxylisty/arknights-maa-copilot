# 每周剿灭作战（camp_r 关）

每周轮换的剿灭委托（米诺斯·灰石剧场等）。MAA **没有**剿灭导航，但 Copilot 能打：
人用 adb 把游戏点到**编队页**，剩下交给 MAA。通关之后的**扫荡不用 MAA**——
用游戏自己的**全权委托**，秒结算（见下文 §全权委托扫荡）。

| 谁 | 干什么 |
|---|---|
| 人/agent（adb） | 在剿灭地图点「开始行动」进编队页；打完点结算、点掉简报 |
| MAA Copilot | 加载作业 → 自动编队 → 打满 400 杀（**每周第一次**） |
| 全权委托 | 通关后的重复扫荡：1 张代理卡秒结算，不用 MAA 不用看录像 |

## 周流程

1. **每周首通（MAA 抄作业）**：下面 §首通流程。
2. **之后每次扫荡（全权委托）**：`annihilation.py` 的 `run_delegation()` 或 MCP
   `annihilation_run`，10 秒完事。**不要用「代理指挥」重放**——那是把 25 分钟
   录像再看一遍，结果固定，纯浪费时间。

## 首通流程（MAA Copilot）

1. **找作业**：剿灭关的 stage code 是 `camp_r_<n>`（灰石剧场 = `camp_r_34`，每周换新编号），
   `levelKeyword=camp_r` 就能搜出全部剿灭作业，再按 `stage_name` 过滤。
   **不要猜 `annihilation_` / `a003_ex` 之类的 code**，那些搜出来全是别的关；
   中文关键词（唐州/剿灭/灰石）对 levelKeyword **无效**——它只匹配 stage code。

   ```python
   import copilot_api as CA
   rows = CA.search_stage("camp_r_34")   # 或先 levelKeyword="camp_r" 模糊找当前关
   box = CA.load_box()
   for nhard, nlow, nv, r, hard, low, fillers in CA.rank(box, rows): ...
   ```

2. **挑作业**：用 `feasible()`（见 SKILL.md §可行性判定），但剿灭要多看两条，见「剿灭特有的坑」。
3. adb 点剿灭主界面右下角「开始行动」**(1725, 985)** 进入编队页。
   **(1400, 950) 会点到「返还规则」奖励弹窗**，别用（back 键返回）。
4. MAA 作业页：路径、`自动编队`✓、`忽略干员属性要求`✓、缺 1 个 6★ 时 `借助战`✓、开始。
5. **验收**：2 倍速全程约 15 分钟，轮询间隔 20s 起。

## 全权委托扫荡（2026-10 实测，自动化在 `annihilation.py`）

确认弹窗原文：`确认使用1张常态事务代理卡 执行一次全权委托代理指挥?`

- **消耗 1 张常态事务代理卡，不扣理智**（按钮区显示 PRTS 图标 -1 而不是 -25）。
  游戏优先烧**最快过期**的那张卡。卡在顶栏 PRTS 徽章旁计数。
- 结算是**瞬时**的：点确认 → 直接 MISSION RESULTS，周报酬进度条 `N/1800` 当场跳。
- 委托按**「最高歼灭数」发合成玉，且不计使用助战的场次**。
  400 杀但用了助战的首通**不会**成为委托记录——所以**首通尽量别借助战**，
  否则委托记录停在低杀数（灰石剧场实测：助战 400 首通后记录仍是 395，
  委托只发 335 玉）。要刷记录就用一份**零助战依赖**的作业重打一次。
- 预计收益显示在确认弹窗里：`当前最高歼灭数 395 → 预计可获得 合成玉 ×335`。

### 地图页右下角的开关语义（吃过亏，别再猜）

默认有两个并排开关 + 蓝色开始按钮：

| 元素 | 坐标 (1920×1080) | 说明 |
|---|---|---|
| 全权委托 复选框 | (1365, 888) | 点它 = 进入委托模式 |
| 代理指挥 复选框 | (1600, 888) | 见下 |
| 开始行动 | (1725, 985) | 委托模式下点它弹确认框 |
| 确认使用 / 取消 | (1710, 990) / (1430, 990) | 确认弹窗的两颗按钮 |
| 结算推进/空白处 | (960, 540) | MISSION RESULTS 连点回地图 |

- 点「全权委托」后：**全权委托那一行整个隐藏**（原位变成 PRTS 徽章装饰），
  同时**「代理指挥」的勾选框变成白色勾选态**——这个白勾是「委托模式已开启」的
  **指示器**，不是代理指挥被勾上了，不要去"纠正"它。
- 勾选态像素判据：未勾 = 深灰 `(38,38,38)`；委托模式 = 白 `(255,255,255)`。
- 点白色勾选框 = 取消委托模式，恢复两行并排的默认布局。
- **代理指挥（重放录像）模式别用**：确认框写「执行一次全权委托代理指挥?」——
  委托是代理指挥的高位替代；重放模式要陪打 25 分钟，结果一样。

### 自动化入口

```python
import annihilation as AN
AN.run_delegation(confirm=False)   # 只弹确认框读收益预览，然后取消
AN.run_delegation()                # 完整执行：勾选→开始→确认→结算→回地图
```

MCP：`annihilation_run(confirm=true)`（需游戏停在剿灭地图页）、
`annihilation_collect`（解析结算页）、`maa_status`（MAA 状态自检）。
**注意**：改过 `ark_mcp.py` 后要重启 ZCode 会话/重连 MCP，新工具才出现。

## 验收

- 首通结束时先弹**作战简报**浮层：`已歼灭 X/400`、`已攻入敌方数`（>0 即漏怪失败）、
  `剩余防御点数`（<10 即失败）——这是**最可靠的战果判据**（OCR 全屏即可）。
- 点浮层 → 「行动结束 MISSION RESULTS」大字页。OCR 用裁剪区域
  (40,230)-(760,480) 找「行动结束」，和 VEC 同一套判定；简报浮层本身 OCR 不到这行，别当失败。
- 委托扫荡直接落 MISSION RESULTS，认 `每周报酬进度 N/1800` 与 `已歼灭`。

## 剿灭特有的坑（实战学费）

- **模组要求是硬门槛，`忽略干员属性要求` 忽略不了它。**
  作业 108125（理雪双核）要求结城理带模组，账号没解锁，MAA 日志写
  `干员不可用: 结城理, 原因: 所需模组未解锁` 但**照样选他上场**，
  结果 395/400 漏 5 个怪失败。挑选作业时，`requirements.module` 非 -1 的核心干员
  如果是较新的干员（可能没解锁模组），优先换「老干员」版作业。
  **选作业时先批量拉 JSON 查 `requirements.module`**（见下 108033 的选择过程）。
- **干员组的兜底替换会让轴漂移。** 组内首选不可用时 MAA 会挑别人
  （`收割者 => 休谟斯`、`先锋 => 凛御银灰(技能等级不足)`），换了人轴就不对了。
  两个候选作业的 hard 缺口数相同时，优先挑**组内成员你全有**的那个。
- OperBoxData.json **没有模组字段**，本地预检查不出模组风险，
  只能看 MAA 编队日志的 `所需模组未解锁` 警告——**编队阶段就该停下来换作业**。
- 零缺口 ≠ 能过：先看模组，再看组内替换风险，最后才轮到播放量。
- **助战场次不计入委托记录**（见 §全权委托扫荡），首通尽量零助战。
- **prts 作业标题会瞎写。** 108011 标题叫「卫戍协议:盟约」，实际就是一份普通的
  camp_r_34 剿灭作业（别按标题脑补出新玩法）。选作业只认 `stage_name`，
  而且进游戏前先确认对应的模式入口真的存在，再加载作业。
